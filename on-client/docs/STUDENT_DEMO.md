## 3. 시연 전 실행 준비

1. 받은 프로젝트를 탐색기로 열고 **on-client**로 들어갑니다. package.json, student, src, tools가 함께 보여야 합니다. 작성자의 D: 경로를 다른 PC에 그대로 입력하지 않습니다.
2. 탐색기 주소 표시줄에 **powershell**을 입력하고 Enter를 눌러 그 위치에서 일반 PowerShell을 엽니다. 관리자 실행은 하지 않습니다.
3. 아래 확인 명령을 한 줄씩 실행합니다. 파일 검사 세 개는 모두 True여야 합니다. 오류가 있으면 다음 단계로 진행하지 않고 [실행 설명서 9장](STUDENT_RUNBOOK.md#9-오류별-확인복구-순서)을 확인합니다.

```powershell
Get-Location
Test-Path -LiteralPath .\package.json -PathType Leaf
Test-Path -LiteralPath .\student\extension.mjs -PathType Leaf
Test-Path -LiteralPath .\tools\start-alekov.ps1 -PathType Leaf
node --version
npm.cmd run check
```

4. 앱이 꺼져 있으면 다음을 실행합니다. 이미 본인 앱이 켜져 있으면 같은 포트에 다시 띄우지 않고 그 앱을 사용합니다. 학생 파일을 다시 읽으려면 브라우저 Ctrl+F5를 누릅니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

기본 시작 문구는 **케셰브가 켜졌습니다**와 http://127.0.0.1:5189/ 입니다. 브라우저에서 실제 출력 주소를 엽니다. Node 기준 버전 참고나 SQLite ExperimentalWarning만으로 실패라고 판단하지 않습니다. PowerShell 창은 앱을 사용하는 동안 열어 둡니다. 서버 응답·계정 연결 준비 문구가 실제 SDP 연결·AI 설명 성공은 아닙니다.

포트 사용 중이면 기존 본인 앱을 먼저 확인합니다. 별도 실행이 필요할 때만 아래를 사용하고 http://127.0.0.1:5190/ 을 엽니다. 다른 프로그램을 종료하지 않습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Port 5190
```

시연은 기본 실행으로 진행합니다. 제공 demo 모드나 계정 승인·유료 AI 요청·실제 조치 집행은 핵심 세 기능 시연에 필요하지 않습니다. 자동 조회는 기본 꺼짐으로 두고, 켜져 있다면 학생/제공 두 PC 영역의 자동 체크를 꺼서 수동 조작과 구분합니다. 포장·내보내기·설치·공격/침투 시험·방화벽/보안 설정 변경은 하지 않습니다.

## 4. 핵심 기능 세 가지 시연 순서

아래의 기대 화면은 **시연 계획**입니다. 이 문서를 작성하며 새로 실행한 결과가 아닙니다. 기존 확인 근거는 6장에 따로 적었습니다. 실제 수치·건수·시각은 시연에서 받은 응답을 읽으며 아래 과거 값을 그대로 재현하려고 부하를 만들지 않습니다.

### 장면 1 — 내 PC 상태: 네 카드와 PC 상세

1. **보호 현황 → 학생 상태·알림 표시 → 케셰브 · 내 PC 관제**를 찾습니다.
2. **1. 내 PC 상태**에서 **다시 조회**를 한 번 누릅니다. **조회 중…** 안내 뒤 현재 시각·네 카드 또는 확인 불가 이유를 보여 줍니다. 요청 중에는 추가 클릭이 새 요청을 만들지 않아야 합니다.
3. CPU 사용률(%), 메모리 사용률(%)·사용/전체(GiB), 드라이브 여유/전체(GiB), 켜진 방화벽 프로필 개수(/3)를 읽습니다. 시각은 서버 조회 완료 기준이며 값별 독립 측정 시각은 제공되지 않는다고 설명합니다.
4. **PC 상세 · 네트워크·방화벽·Windows 기록·SDP**를 펼칩니다. 네트워크 인터페이스·IPv4 구성 개수, 방화벽 프로필별 설정, Windows 기록 합산 건수 또는 확인 불가 이유를 확인합니다. C:·D: 등 실제로 받은 고정 로컬 볼륨만 보여 줍니다.
5. 별도 SDP 상태를 읽습니다. 현재 확인 기록의 **SDP 미연결**을 정상 연결로 바꾸지 않습니다. PC 값이 읽혔다고 SDP 연결이 된 것은 아닙니다.

설명 예: “측정은 제공 기능을 사용하고 저는 결과 카드와 조회·실패 안내를 정리했습니다. Windows 경고·오류 건수는 침해나 공격 탐지 결과가 아닙니다. 읽지 못한 값은 확인 불가로 남깁니다.”

### 장면 2 — 실측 추이·직전 비교

1. 잠시 뒤 **다시 조회**를 한 번 더 누릅니다. **2. 실측 추이·비교**로 이동합니다. 두 응답이 실제로 확인된 경우에만 두 표본을 비교합니다.
2. CPU·메모리 추이와 **시각별 실측 표**에서 각 표본의 시각·값을 읽습니다. 현재 페이지에서 받은 최근 120회만 유지하고, 새로고침하면 초기화됩니다. 측정하지 않은 구간에 값을 채우지 않습니다.
3. **직전 실측과 비교한 변화 설명**에서 전후 시각과 값을 확인합니다. 사용률의 차이는 퍼센트포인트(%p), 메모리 사용량·드라이브 여유 차이는 GiB입니다. 첫 표본·직전 결측·범위 변경이면 비교 확인 불가가 맞습니다.
4. 표시가 같은 두 값에도 작은 변화가 있을 수 있습니다. 차이는 원래 값으로 계산한 뒤 소수 한 자리로 표시하므로 반올림 차이와 표시 정밀도 안내를 함께 읽습니다. 변화만으로 원인·침해·안전을 단정하지 않습니다.

설명 예: “저는 제공 조회의 두 실측을 비교하는 설명을 추가했습니다. 같은 범위의 값이 확인될 때만 계산하고, 결측을 오래된 정상 값으로 대신하지 않습니다.”

### 장면 3 — 이 앱의 조회 기록·필터·상세

1. **3. 조회 기록**에서 표시 건수와 이번 페이지의 기록 수, 기록의 시각을 읽습니다. 페이지 메모리의 최근 100건이며 영구 저장 원장이나 실제 XDR 경보 목록이 아닙니다.
2. **조회 기록 필터**에서 현재 받은 기록의 종류에 맞게 실측 확인·일부 확인 불가 등을 선택하고 전체로 되돌립니다. 해당 종류가 없어서 표시 0건이 되면 필터 결과이며 조회 실패가 아닙니다.
3. 한 기록의 펼침을 열어 출처, 확인 불가 항목과 당시 요약을 읽습니다. 실제 Windows 기록이 확인 불가인 경우 일부 확인 불가로 남겨야 합니다.
4. 가능하면 Tab·Shift+Tab으로 이동하고, 버튼/펼침은 Enter 또는 Space, 체크박스는 Space, 바로가기 링크는 Enter, 필터는 기본 선택 상자 키보드 조작으로 보여 줍니다. 지원하지 않는 조치나 원천 요청 버튼을 새로 누르지 않습니다.

설명 예: “이 기록은 제 앱이 PC 상태를 조회한 이력입니다. Windows 원천 이벤트나 저장된 XDR 보안 경보와 구분했습니다.”

### 선택 설명 — 예시 분리와 실패 처리

- 예시를 보여 줄 때는 자동 조회를 끄고 시각·기록 수를 먼저 읽은 뒤 **설명용 예시 보기 (실측과 별도)**를 선택합니다. **측정 시각 없음·실제 조회 결과 아님** 영역만 보여 줍니다. 실측 비교·추이·기록을 대신한 값이 아닙니다. 토글 전후 집계 불변은 기존 실제 화면에서 분리 확인하지 못했으므로 시연에서 확인하지 못하면 계속 미확인으로 둡니다.
- 조회에 실패하면 항목·안전한 이유와 다음 행동을 읽습니다. 실패를 만들려고 권한·방화벽·운영 정책을 바꾸지 않습니다. 서버 중지/재실행 시연을 별도로 선택한다면 브라우저를 연 채 본인 실행 창에서 Ctrl+C → 학생 다시 조회 → 같은 시작 명령으로 재실행 → 학생 다시 조회 순서입니다. 과거 기록과 현재 실패를 구분합니다.
- 60초가 지나 현재 값이 확인 불가가 되면 오래된 값 처리라고 설명하고 직접 다시 조회합니다. 과거 표본·조회 기록은 시각과 함께 남습니다. 기다리는 동안 예시로 채우지 않습니다.
