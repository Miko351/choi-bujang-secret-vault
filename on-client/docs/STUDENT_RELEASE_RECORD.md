## 2. 실제 수행한 절차

다음 명령은 원본 폴더를 이동하거나 덮어쓰지 않고 GitHub에서 새 경로로 받았습니다. 재현 경로가 이미 있으면 중단하고 덮어쓰거나 삭제하지 않습니다.

```powershell
Set-Location -LiteralPath 'D:\'
if (Test-Path -LiteralPath '.\ALEPH_choi-bujang-secret-vault-repro-22-97de193') {
  throw '재현 폴더가 이미 있습니다. 덮어쓰지 않습니다.'
}
git clone --no-checkout --single-branch --branch main https://github.com/Miko351/choi-bujang-secret-vault.git .\ALEPH_choi-bujang-secret-vault-repro-22-97de193
git -C .\ALEPH_choi-bujang-secret-vault-repro-22-97de193 checkout --detach 97de1935c68cd5be70c39d2d1fe2d5e2452f7958
git -C .\ALEPH_choi-bujang-secret-vault-repro-22-97de193 rev-parse HEAD
```

참고 절차로 단순 복사한 폴더가 아니라, 실제로 위 저장소의 해당 커밋을 새로 받았습니다. 도구 실행 시 Git 소유권 경계를 확인하기 위해 해당 경로에만 명령 단위 `safe.directory`를 사용했고, Git 전역 설정이나 원본 기록을 변경하지 않았습니다.

새 앱 위치에서 실행한 준비·실행 명령입니다.

```powershell
Set-Location -LiteralPath 'D:\ALEPH_choi-bujang-secret-vault-repro-22-97de193\on-client'
node --version
npm.cmd run check
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Port 5191 -Background
```

제공 런처가 새 프로젝트용 계정 연결 준비, Node.js 버전 참고와 HTTP 준비 완료를 출력했습니다. 5191은 원본 앱의 기본 5189와 구분하려고 명시한 포트입니다. `-Background`는 제공 런처에 있는 옵션이며 이 준비 재현에서 실제 사용했습니다. 별도 앱의 경로·PID와 포트 소유를 확인한 뒤 **해당 복제본 서버만** 종료했고, 5191의 GET이 연결 실패하는 것을 확인했습니다. 같은 명령으로 재실행한 뒤 독립 GET의 HTTP 200을 확인했습니다. 원본 앱의 다른 프로세스는 종료하지 않았습니다.

첫 중지·재시작 점검에서는 PowerShell 변수로 백그라운드 실행 출력을 모아 받다가 자식 서버가 출력 스트림을 유지해 점검 스크립트가 대기했습니다. 서버 자체는 독립 GET으로 200이었지만, 캡처를 정리하려고 해당 자식만 중지한 뒤 최초 점검의 후속 GET은 연결 실패했습니다. 이 실패를 지우거나 앱 성공으로 합산하지 않았습니다. 앱 코드를 고치지 않고 **실행 도구 호출과 HTTP 확인을 별도 호출로 분리**하여 재시작·HTTP 200을 확인했습니다. 세부 경과는 증거 JSON의 `stopRestart`에 있습니다.

일반 사용자가 창에서 직접 종료·재실행할 때는 [21단계 설명서](STUDENT_RUNBOOK.md)의 전경 실행과 Ctrl+C 절차를 따릅니다. 백그라운드로 켰다면 런처가 알려 준 프로세스 번호와 이 복제본 경로·포트 소유가 일치하는지 확인하고 그 프로세스만 중지합니다. 모든 node를 종료하거나 폴더를 지우는 명령은 사용하지 않습니다.

## 4. 이동 가능한 구성과 비밀 설정

실행에 필요한 제공 소스·학생 extension·문서·package.json은 같은 Git 커밋에 있습니다. 루트의 기존 자료실용 package.json/package-lock.json과 on-client 로컬 앱의 설치 조건을 구분합니다. 이 앱은 외부 npm 의존성 0이며 이번 재현에서 npm install이 필요하지 않았습니다. 원래 폴더의 node_modules나 캐시를 복사하지 않았습니다. 레거시 자료실을 별도 운영하는 의존성 설치·DB 연결은 이번 on-client 재현에 실행하지 않았습니다.

실행 코드가 특정 `D:\...` 작업 경로를 상수로 요구하는 방식으로 변경되지 않았습니다. 위 절대 경로는 **이 PC의 실제 관찰 위치**입니다. 다른 환경에서는 받은 저장소의 `on-client`를 현재 작업 폴더로 열고 다음처럼 상대 진입점을 사용합니다.

```powershell
npm.cmd run check
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

제공 `.env.example`은 비밀 없는 이름·기본 형식 참고용이고 런처가 운영 자격을 자동으로 읽어오는 파일이 아닙니다. 기존 `.env`·인증서·개인키·토큰·개인 호스트 설정을 새 폴더나 제출물에 그대로 복사하지 않습니다. 새 경로의 기본 계정 연결은 제공 도구가 프로젝트 밖 Windows 개인 저장소에 준비합니다. 이후 계정 확인·AI 앱 승인은 사용자가 직접 해야 하며 새 폴더라는 이유로 권한을 승계하지 않습니다. 원천 SDP·OSV·실집행 설정은 담당자가 검증한 연결이 있을 때만 사용합니다. 주소·모델·운영자 권한을 학생이 추정해서 만들지 않습니다.

지원 환경은 검증한 Windows·Node v22.18.0·Windows PowerShell 5.1이며 제공 코드의 Node 범위와 다른 환경 검증은 구분합니다. Linux/macOS·다른 Windows 계정·완전히 새 PC와 설치형 패키지 전체 앱의 재현은 미실행입니다. 이번에 새로운 수료 ZIP·설치 프로그램을 만들거나 기존 앱 파일을 바꾸지 않았습니다.

## 6. 22단계 최종 커밋으로 이어갈 순서

이 문서의 표와 stage22-preparation.json은 97de193…의 준비 재현 기록입니다. 문서 작성 시점에는 22단계 저장점이 아직 없어 제출 커밋 자체의 재현은 미실행입니다. 저장점 생성 뒤에는 실제 해시를 고정한 새 checkout에서 다시 점검하고, 그 결과를 프로젝트 밖의 커밋별 final-result.json으로 보관합니다. 커밋 후 생성되는 증거와 준비 기록을 구분하며, 준비 결과를 최종 커밋의 결과로 바꾸지 않습니다. 후행 증거에는 정확한 커밋·버전·환경·시각·GET 결과·모의 표시·미실행·사용자 확인 범위를 기록합니다.

1. 문서·증거·README의 실제/모의/미실행 구분과 비밀값 제외를 검토한 뒤 같은 저장점에 저장합니다. 생성된 40자리 해시는 `git rev-parse HEAD`로 확인합니다. 기존 staged 작업이 있으면 먼저 보존합니다.
2. 그 최종 해시를 GitHub에 올렸다면 **다른 새 빈 경로**에 같은 저장소를 clone하고, `git checkout --detach` 뒤에 실제 최종 해시를 지정합니다. 준비에 쓴 97de193… 폴더의 결과를 재사용하지 않습니다. 이번 문서에는 아직 없는 최종 해시·경로를 만들어 적지 않습니다.
3. 최종 checkout의 실제 HEAD, package.json·설정 견본·lock 유무와 필요한 파일을 대조하고, 같은 런타임·실행·브라우저·중지·재실행 순서로 확인합니다. 파일이 같다는 것과 실제로 명령을 다시 실행했다는 것을 구분합니다. 코드나 의존성을 고쳤다면 새 커밋으로 이 절차를 다시 고정합니다.
4. 새 결과는 정확한 커밋과 함께 별도 증거로 보관합니다. 서로 다른 커밋의 정상·금지·운영 결과를 합쳐 전체 성공으로 기록하지 않습니다. 이 문서에 미완료라고 남긴 항목은 해당 최종 커밋에서 직접 확인하기 전까지 그대로 유지합니다.
5. 21·22단계 과제 화면에 저장소 URL과 실제 최종 40자리 커밋을 직접 입력합니다. 공식 AI의 원문 검토와 학생의 재현 진술·도구 실행은 별개이며 운영 인증이 아닙니다.

비공개 저장소는 공개로 바꿀 필요가 없습니다. 원문 전달이 필요하면 해당 단계의 **비공개 저장소 원문 준비 방법**에서 받은 도구·명령을 따릅니다. 도구 ZIP과 출력 JSON은 프로젝트 밖에 두고 Git 최상위에서 실제 commit을 지정합니다. 구체적인 `student-source-cli.mjs` 명령은 아직 제공받지 않았으므로 임의로 쓰거나 실행하지 않았습니다. 원문 전달만 실패하면 기존 접수를 유지하고 **원문만 다시 보내기**를 사용합니다. 과제 제출·공식 통과는 이번 준비 재현에서 미실행입니다.

## 7. 재현용 복제본 정리

사용자는 모든 확인과 증거 보관이 끝난 뒤 재현용 복제 폴더를 제거하도록 요청했습니다. 정리는 이번 작업에서 만든 준비·최종 재현 폴더와 그 경로에서 시작한 서버에 한정합니다. 삭제 전에 절대 경로·작업 트리·프로세스 경로와 포트 소유를 확인하며, 사용자 작업이 추가되었으면 보존하고 중단합니다. 결과 JSON과 원본 학생 문서는 복제본 밖에 보관한 뒤 정리합니다. 원본 저장소·Git 기록·학습 DB·기존 개인 자격 저장소는 정리 대상이 아닙니다. 이 문서를 쓰는 시점의 정리는 미실행이며 최종 증거에 실제 정리 결과를 남깁니다.
