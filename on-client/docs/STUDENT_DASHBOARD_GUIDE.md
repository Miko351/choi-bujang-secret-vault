## 여러 드라이브와 단위

Windows의 Win32_Volume에서 드라이브 문자가 있는 고정 로컬 볼륨을 읽습니다. 볼륨 ID는 PowerShell 내부 중복 제거에만 쓰고 응답에는 드라이브 문자·용량만 나갑니다. 볼륨 라벨·사용자·파일명·볼륨 GUID는 반환하지 않습니다. 네트워크 드라이브·이동식·문자 없는 볼륨은 이번 합계 범위가 아닙니다. 물리 디스크 개수와 논리 볼륨 합계를 같은 것으로 표시하지 않습니다.

`metrics.drives`는 선택적 새 필드입니다. 각 볼륨의 id·state·totalBytes·freeBytes와 확인된 볼륨 합계·확인 불가 개수를 담습니다. C:·D: 각각의 여유 공간을 먼저 확인하고 합계는 보조로 봅니다. 한 볼륨이 가득 찼어도 다른 볼륨의 여유로 문제가 가려지지 않게 드라이브별 내용을 유지합니다. 읽지 못한 항목을 0으로 채우지 않으며, 모두 확인 불가이면 합계 용량도 만들지 않습니다.

기존 `metrics.disk`는 앱이 있는 볼륨의 응답으로 그대로 유지했습니다. 예전 서버가 살아 있어 새 필드가 없으면 학생 화면은 앱 볼륨만 확인했다고 안내하며 C:·D:를 임의 생성하지 않습니다. 비 Windows에서는 새 드라이브 조회를 지원 없음으로 두고 기존 단일 디스크 조회를 보존합니다.

표시 단위는 **GiB = bytes / 1024³**입니다. 기존 제공 화면은 이 계산에 GB라는 표기를 붙였으나 이번 승인 범위에서 GiB로 바로잡았습니다. 예를 들어 347.0 GB(10진수)는 약 323.2 GiB와 같은 양이며, 이것은 설명용 환산이지 이번 새 코드의 실측 결과가 아닙니다.

## 사용자가 직접 실행·재실행

서버 실행·재실행은 사용자가 직접 합니다. 이 작업에서 AI는 서버를 새로 켜지 않았으며 포장 명령도 실행하지 않았습니다. 이미 실행 중인 서버는 해당 실행 창에서 Ctrl+C로 중지한 뒤 다음 명령을 실행합니다. 다른 node 프로그램을 일괄 종료하지 않습니다.

```powershell
Set-Location -LiteralPath 'D:\ALEPH_choi-bujang-secret-vault\on-client'
node --check .\student\extension.mjs
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

브라우저에서 http://127.0.0.1:5189/ 을 열고 Ctrl+F5로 새 학생 파일을 읽습니다. PC 서버 모듈도 바뀌었으므로 브라우저 새로고침만으로는 여러 드라이브가 적용되지 않습니다. 실제 런처 종료·재시작이 필요합니다. 정상 시작 문구는 **케셰브가 켜졌습니다**와 위 주소입니다. Node v22.18.0 참고와 SQLite 경고만으로 실패를 판정하지 않습니다.

구현 직후에는 문법·모의 검사만 했습니다. 이후 2026-10-29 사용자가 아래 실제 조회 화면을 확인해 알려 주었습니다. 실측 카드·드라이브 목록과 합계·추이 표본·조회 기록은 사용자 보고로 확인했으며, 실제 그래프 선의 시각적 배치·키보드 초점·자동 주기·예시 토글의 집계 불변·필터·서버 중지 실패 화면은 아직 미확인입니다.

## 확인 순서

1. **보호 현황 → 학생 상태·알림 표시(renderStatus)**의 **케셰브 · 내 PC 관제**를 찾습니다. 조회 전 카드에는 확인 불가가 표시되고 예시는 기본으로 꺼져 있어야 합니다. 기존 기기·진단 기능은 아래 펼침 영역에서 확인합니다.
2. **학생 PC 실측 조회**를 한 번 누릅니다. 실측 시각·네 카드·드라이브별 C:·D: 및 확인된 합계를 봅니다. Windows 기록이 읽히지 않으면 확인 불가이며 0건이 아닙니다. 접근 가능한 드라이브의 실제 구성은 PC마다 다릅니다.
3. 다시 조회해 CPU·메모리의 실제 표본과 조회 기록이 늘어나는지 확인합니다. 표본 사이에 확인하지 못한 값은 0으로 그리지 않습니다. 그동안 측정한 구간만 나타나야 합니다.
4. **설명용 예시 보기**를 켰다가 끕니다. 별도 예시 영역만 바뀌며 실측 카드 값·표본 수·실제 조회 기록 수는 증가하지 않아야 합니다.
5. **조회 기록 필터**를 바꿔 내용과 건수가 맞는지, 상세에 실측/확인 불가의 근거가 있는지 봅니다. Windows 원천 이벤트 목록과 이 앱의 조회 기록은 서로 다릅니다.
6. 필요할 때만 **10초마다 실측 (보이는 동안)**을 켭니다. 기본은 꺼짐입니다. 다른 탭으로 가면 자동 조회를 멈추고 돌아오면 사용자가 켜 둔 경우에만 이어집니다. 제공 **내 PC 확인**과 학생 조회는 별도이므로 자동 조회는 사용할 한쪽만 켜는 것이 좋습니다.
7. 실패 확인은 직접 서버를 중지한 뒤 열린 브라우저의 학생 조회 버튼을 눌러 봅니다. 현재 카드는 확인 불가, 기록은 조회 실패로 남아야 합니다. 서버를 직접 재실행하고 재조회하면 새 값으로 바뀌어야 합니다. 기존 자료·정책을 지우거나 권한을 바꿔 실패를 만들지 않습니다.

이번 실제 PC에서의 확인을 완료하기 전에는 이 안내를 실행 성공·운영 보호·새 제출 통과 기록으로 사용하지 않습니다. 실제 AI 추론·원천 엔진·집행·OSV 조회의 기존 미실행 상태는 이 대시보드가 바꾸지 않습니다.

각 값의 시각은 서버 응답의 measuredAt, 즉 **조회 완료 시각을 실측 기준 시각**으로 사용합니다. 개별 항목을 읽은 정확한 시각은 응답에 없으므로 따로 측정했다고 꾸미지 않습니다. CPU는 약 200ms 구간의 사용률, 메모리는 %·GiB, 드라이브는 여유/전체 GiB, 방화벽은 켜진 프로필 개수/3으로 표시합니다. 예시 영역에는 측정 시각이 없으며 실제 조회 결과가 아니라고 표시합니다.

바로 앞의 서로 다른 시각 표본 하나와만 비교합니다. 중간 표본에 결측이 있어도 더 오래된 정상 값으로 건너뛰지 않습니다. 현재 조회 중·실패·60초 경과이면 현재 비교를 지우고 확인 불가로 둡니다. 과거 추이와 조회 기록은 날짜가 있는 이력으로만 남습니다. 첫 표본은 직전 값 없음으로 안내합니다. 시간 순서를 확인할 수 없으면 비교하지 않습니다.

메모리는 전체 용량이 같을 때 비교하며, 드라이브는 같은 문자와 전체 용량이 모두 확인된 경우에만 비교합니다. 드라이브 추가·제거·권한 실패·용량 변경은 비교 확인 불가와 이유를 보여 줍니다. 이 조건은 논리 볼륨의 비교 범위 확인이며 물리 디스크의 동일성을 인증하지 않습니다. 서로 다른 드라이브 집합의 합계 차이를 저장 공간 사용 변화로 해석하지 않습니다. 차이는 소수 한 자리로 표시하고 그보다 작은 차이는 표시 정밀도보다 작다고 덧붙입니다. 변화만으로 원인·침해·안전을 단정하지 않습니다.

원인 코드는 허용된 고정 한국어 설명으로 바꿉니다. permission_denied는 일반 권한으로 읽을 수 없다고 표시하며 관리자 실행을 안내하거나 권한을 높여 재시도하지 않습니다. query_failed·timeout·unsupported·cancelled·잘못된 응답도 0 또는 예시 값으로 채우지 않습니다. 제공 화면과 학생 화면의 버튼·마지막 조회 상태는 계속 별도이며 같은 API를 사용합니다.

### 이번 추가의 확인 범위

확인한 것은 문법 검사와 모의 DOM·API 검사입니다. 두 표본의 %p/GiB 계산, 최초 표본, 현재/직전 결측, 메모리·드라이브 전체 용량 변경, 드라이브 추가·제거, 예시 토글의 비교 불변, 실패·오래됨의 현재 비교 제거, 제공 카드의 시각·일반 권한 실패 안내를 모의 응답으로 점검했습니다. 기존 여덟 렌더러와 OS 측정 모듈은 Git 원문과 줄바꿈을 정규화해 대조했습니다. 원문 비교 검사의 CRLF/LF 차이와 모의 문서 초기화 누락은 검사 방법을 바로잡았으며 이 때문에 앱 코드를 바꾸지 않았습니다. 이 모의 값은 실제 PC 실측이나 화면 확인 결과가 아닙니다.

**구현 직후에는 실제 브라우저 확인을 미확인으로 두었으며, 이후 사용자 확인 결과는 아래 표에 따로 기록합니다.** 앱 시작·재시작은 사용자가 직접 하며 기존 서버·제출물·Git 기록은 보존합니다. 이번에는 학생 파일과 제공 화면 파일만 바뀌었고 OS 수집 모듈은 바꾸지 않았습니다. 열린 앱에서 Ctrl+F5로 읽은 뒤 확인할 수 있습니다. 서버가 꺼져 있다면 위의 기존 시작 명령을 사용합니다.

1. 보호 현황의 학생 PC 관제에서 **학생 PC 실측 조회**를 한 번 누릅니다. 각 카드의 단위·서버 조회 완료 시각을 확인하고, 직전 비교에는 표본이 없다는 안내가 나오는지 봅니다.
2. 잠시 뒤 같은 버튼을 다시 한 번 누릅니다. **직전 실측과 비교한 변화 설명**에서 두 시각과 CPU·메모리·드라이브의 전후 값을 대조합니다. 두 사용률의 차이는 상대 변화율(%)이 아니라 퍼센트포인트(%p)입니다.
3. **설명용 예시 보기**를 켜도 실측 비교·표본 수·실제 조회 기록 수가 바뀌지 않아야 합니다. 예시는 측정 시각 없음으로 표시돼야 합니다.
4. 제공 기능과 비교하려면 **내 PC 확인**을 별도로 누릅니다. 두 버튼은 서로 다른 시각에 조회하므로 값이 같을 필요는 없습니다. 각 시각·단위를 따로 대조합니다.
5. 읽지 못한 항목은 확인 불가와 이유가 나와야 합니다. 실제 권한·운영 설정을 바꾸어 실패를 만들 필요는 없습니다. 서버 중지 시험을 직접 한다면 열린 페이지에서 조회 버튼을 눌러 이전 값이 현재 비교로 남지 않는지 확인하고 서버를 다시 실행합니다.
